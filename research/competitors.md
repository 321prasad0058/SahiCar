## 1. The `rea` tool (github.com/morluto/rea)

**What it is.** REA ("Reverse Engineer Anything"), npm package `rea-agents` v6.8.0, MIT licence. It is a local **MCP server + CLI** written in TypeScript (Node 22+) that gives an AI coding agent (Claude Code, Codex, Cursor, Gemini CLI…) a large catalogue of reverse-engineering tools. Pitch: *"See a feature you like. Understand how it works, down to the binary level."* Repo: https://github.com/morluto/rea · site: https://rea.tools/

I cloned it (depth 1) to the scratchpad and read the README, `DISCLAIMER.md`, `docs/browser-observation.md`, `docs/website-script-export.md` and the `src/` layout. **I did not install or run it, and did not point it at any site.**

**How it works.**
- `src/server/*` registers ~dozens of MCP tools (`registerBrowserScenarioTool.ts`, `registerAndroidTools.ts`, …); `src/cli.ts` exposes the same workflows as `rea <command>`. Every result is returned as an **"Evidence" record** (what was observed, provenance, coverage/limitations), which an agent then reasons over.
- Back-ends by target: native binaries via Hopper/Ghidra/IDA/Kuna/Rizin/objdump; static parsers for Go/Rust/.NET/PE/ELF/WASM/APK/Flutter/IL2CPP/SQLite/model files; Frida/GDB for runtime; tshark for pcaps; JADX/Apktool/adb for Android.
- **Websites** (`src/browser/Cdp*.ts`, uses `playwright-core` + Chrome DevTools Protocol): it *attaches to a Chrome-family browser you already have open* (explicit `--remote-debugging-port`) and passively records the page you are on. Tools:
  - `list_browser_targets` – tabs at the CDP endpoint (optionally filtered to one origin).
  - `inspect_web_page` – DOM structure, accessibility tree, script & resource inventory, network/console metadata during an attach window, workers, storage quota, optional script sources.
  - `analyze_web_bundle` – parses captured JS **without executing it**: chunk graph, route & API-endpoint candidates, **vendor fingerprints** (framework/library detection), source-map evidence if public source maps exist.
  - `observe_web_session` – records navigations/redirects/SPA route changes while *you* click around.
  - `export_web_scripts` → `analyze_javascript_application` – dump captured scripts to disk and run the static JS analyser (modules, imports, routes).
  - `capture_web_screenshot`, `compare_web_captures`, `compare_web_screenshots` – before/after diffs.
  - Also: HAR/Fiddler SAZ capture analysis, and an "RL environment" builder that turns a recorded HAR of an app's API into callable tools.
- Its DISCLAIMER explicitly excludes bypassing bot protection/access controls, copying proprietary code/assets, and "unlawful collection … of data"; it says public availability does not by itself establish permission.

**Legitimate use for SahiCar (front-end architecture study only).**
Use it the way you'd use Chrome DevTools/Wappalyzer, on pages you visit normally as an ordinary user:
1. Open e.g. a CarWale model page in your own Chrome (started with a debug port), browse normally, then run `inspect_web_page` + `analyze_web_bundle` on that tab.
2. Questions it can answer: Which framework/rendering model (Next.js/React SSR vs ASP.NET vs Angular)? What JS weight per page and how many chunks? Which third-party tags (GTM, ad servers, chat widgets, A/B tools)? How is the page structured (sections, headings, accessibility tree, schema.org JSON-LD)? Which **categories** of public data a page exposes (price block, spec table, variant list, EMI widget, 360 viewer) and whether it's server-rendered (SEO-friendly) or client-fetched?
3. Record **conclusions** (e.g. "spec pages are SSR'd, ~40 sections, variant list lazy-loaded") — not their data.

**Guard-rails (do NOT cross):** don't harvest/export their spec, price or review databases (Indian law protects databases as literary compilations — *Burlington Home Shopping v. Rajnish Chibber*, Delhi HC 1995 — and all these sites' ToS forbid scraping); don't replay their private APIs, don't use the HAR→"RL environment" feature on competitor APIs, don't evade bot protection, respect robots.txt, keep request volume at human-browsing level, delete captured script bundles after analysis (they're copyrighted code). Lower-risk alternatives that give 80% of the answer: Wappalyzer/BuiltWith public lookups, `view-source:`, Lighthouse/PageSpeed Insights, public sitemaps.

## 2. Competitors

Ownership map (2026): **CarDekho Group** = CarDekho, ZigWheels, BikeDekho, PowerDrift, InsuranceDekho, Rupyy. **CarTrade Tech** (listed) = CarWale, CarTrade, BikeWale, OLX India, Shriram Automall, Adroit/CarTrade Exchange. **Cars24** = Cars24 + Team-BHP (acq. Apr 2025) + CarInfo. **Spinny** = Spinny + Autocar India/Autocar Professional/What Car? India (acq. Haymarket SAC, Mar 2025). **ACKO** = ACKO Drive. OEM-owned: Maruti True Value, Mahindra First Choice. Independent: V3Cars, Droom.

> Key insight for SahiCar: **every large "research" brand is now owned by a transaction business** (dealer lead-gen, used-car inventory, insurance or loans). Even Team-BHP and Autocar India — historically the most trusted voices — now sit under used-car retailers. A genuinely unconflicted advisor is an open niche.

### Standard parameter set shown by the big research portals (CarDekho / CarWale / ZigWheels / CarTrade / V3Cars)
Per model → per variant:
- **Price:** ex-showroom (by city), **on-road price** breakup (RTO/road tax, insurance, TCS, FASTag, "other charges", optional accessories/extended warranty), price trend, offers/discounts, waiting period, **EMI calculator** (down-payment, tenure, rate), loan offers (lead form).
- **Engine & transmission:** engine type/code, displacement, cylinders, valves, max power & torque (@rpm), gearbox type & gears, drive type, turbo, mild/strong hybrid, emission norm.
- **Fuel & performance:** fuel type, ARAI/claimed mileage, user-reported/city & highway mileage, tank capacity, top speed/0-100 (sometimes); **EV:** battery kWh, claimed/MIDC range, real-world range, motor power, AC/DC charging times, charger rating, battery warranty.
- **Suspension, steering & brakes:** front/rear suspension, steering type, turning radius, brake types, tyre size, wheel size, spare.
- **Dimensions & capacity:** L×W×H, wheelbase, ground clearance (laden/unladen), kerb weight, boot space, seating, doors.
- **Comfort & convenience** (~40 yes/no items: power windows, auto climate, rear AC vents, cruise, keyless/push start, ventilated seats, sunroof, powered seat, wireless charger…), **Interior**, **Exterior** (LED lamps, alloys, roof rails…), **Safety** (airbag count, ABS/EBD, ESC, hill assist, ISOFIX, TPMS, 360 camera, NCAP stars, **ADAS** sub-features), **Entertainment & connectivity** (screen size, Android Auto/Apple CarPlay wired/wireless, speakers, connected-car app).
- **Variants explained / "which variant to buy"**, variant-vs-variant feature diff, **compare tool** (2–4 cars side-by-side), **colours** (swatches + images), **image gallery**, **360° exterior & interior views**, videos, **expert review + verdict + pros/cons**, **user reviews & ratings**, Q&A/FAQs, **service/maintenance cost** schedule, **brochure download**, dealer & service-centre locator, test-drive booking, upcoming cars & launch dates, news, rivals list, sales numbers, safety-rating pages, used-car listings/valuation of the same model.

### What SahiCar can do better (gaps none of them fill)
1. **No lead forms, no sponsored ranking** — publish a clear "how we make (no) money" page.
2. **Variant-value scoring** that says "skip this variant" (V3Cars does this partly; portals avoid it).
3. **Total cost of ownership** (on-road + 5-yr fuel at the user's state price + insurance + service + resale) — portals show pieces, never the total.
4. **"Wait or buy"** guidance using upcoming launches, facelifts, and state EV-policy expiries (e.g. Telangana EV waiver ends 31 Dec 2026).
5. **Safety-first defaults** (BNCAP/GNCAP stars, 6 airbags, ESC) surfaced, not buried.
6. Lightweight static pages (Firebase Spark) vs their 2-5 MB ad-heavy pages.

## 3. Where do they get the data? (and what SahiCar can legally use)

Legend: **FREE-OK** = free and usable by us (facts, with attribution/link) · **FREE-LINK** = free to read, copyrighted expression — extract facts, link, don't copy text/images · **PAID** · **NO** = don't use.

### Practical data pipeline for SahiCar (free, Spark-plan compatible)
1. Per model: OEM page/brochure → facts into `research/*.json` (fields per `SCHEMA.md`), `sources[]` + `verifiedOn`.
2. Safety: BNCAP/GNCAP result pages.
3. Images: Wikipedia/Wikimedia Commons via the `wiki` title (attribution shown).
4. On-road: `onroad.json` (state tax + TCS + FASTag + IRDAI-based insurance %), refreshed after each state budget/EV-policy change.
5. Running cost: fuel/electricity from PPAC/OMC/DISCOM monthly.
6. Market context: FADA/VAHAN monthly (manual).
7. Opinions: our own summary + outbound links to Team-BHP/Autocar/CarWale reviews.
